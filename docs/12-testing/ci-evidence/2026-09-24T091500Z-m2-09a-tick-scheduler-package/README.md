## What changed

- New workspace package `packages/tick-scheduler` (`@wasla/tick-scheduler`): `src/scheduler.ts` (pure logic, injected `env`/`fetch`/`now`/`log`), `src/main.ts` (thin entry), `scripts.start = node --import tsx src/main.ts`. The image entrypoint resolves it through `WASLA_SERVICE`.
- Removed `scripts/tick-scheduler.mjs` and `scripts/__tests__/tick-scheduler.test.ts` (single source of truth).
- New production role `tick-scheduler` in `PRODUCTION_GRANTS`, with five grants, each limited to the target's tick scope. The scheduler signs through five literal `createServiceRequestSigner` sites, so the static check 16 reads them and `assertSignerComposition` enforces them at runtime. Matrix doc §3 has five new rows. Two new mutation cases in `gov-cases-authz-policy.sh`, broadening a scope and deleting the grant, both make check 16 fail.
- Terraform: no `start_command`; `plan = "starter"` (owner-approved; cron jobs are paid-only); `WASLA_TICK_TIMEOUT_MS = 90000` so free staging services have time to wake.
- A 503 is now a named `unavailable` outcome and makes the run exit 1. Ticks are sent as POST with no body.
- Guard rebuilt with 19 gates: it resolves the package through `resolve-package.mjs`, asserts the start command, checks that Terraform does not override the entrypoint, checks that all 5 jobs and their URLs are present, and checks that no remnants of the old script remain. Mutation check: adding `start_command` makes it fail (1 failed).
