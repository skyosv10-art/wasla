## 2. الإصلاح

`_runs_lookup` في `scripts/checks/audit-ci-verdicts.sh`، ووضعُ `run-lookup <FULL_SHA>` في `scripts/checks/lib/audit_runs.py` (يحلُّ محلَّ `run-id`):

| صنفُ الجوابِ الواحد | المعنى | الأثر |
|---|---|---|
| `found <id>` | سيرُ `WASLA CI` و`head_sha` = البصمةُ الكاملةُ المسؤولة | يُعتمَدُ معرِّفُهُ فورًا؛ لا تمحوهُ لقطةٌ لاحقة؛ تُسألُ وظائفُ **هذا** المعرِّف |
| `empty` | JSON صالحٌ بقائمةِ `workflow_runs` بلا سيرِ WASLA CI | تُعادُ المحاولة |
| `invalid` | ليسَ JSON · بلا قائمة · نصٌّ فارغ · سيرٌ لبصمةٍ أخرى · معرِّفٌ غيرُ عدديٍّ | تُعادُ، ولا يُقبَلُ بعدَها `no_verdict` |
| خطأُ واجهةٍ بعدَ محاولاتِ `_gh_read` | — | توقُّفٌ فوريٌّ «غيرُ محسوم» ⇒ إخفاق |

- `no_verdict` يُقبَلُ **فقط** إن كانت المحاولاتُ كلُّها مكتملةً صالحةً فارغة بعدَ استنفادِ الحدّ؛ وأيُّ محاولةٍ غيرِ صالحةٍ أو متعذّرةٍ بلا دليلٍ إيجابيٍّ ⇒ **إخفاقٌ معلَن** لا `no_verdict` ولا جزئيٌّ صامت.
- البصمةُ يجبُ أن تكونَ 40 خانةً ستَّ عشريّةً قبلَ سؤالِ القائمة (وإلّا إخفاق)، والقارئُ يرفضُ وسيطًا مختصرًا.
- الحدودُ: `AUDIT_EMPTY_ATTEMPTS` (4) و`AUDIT_EMPTY_WAIT` (2 ث، مضاعَفٌ: 2+4+8 = 14 ث أقصى لكلِّ صفٍّ `no_verdict` حقيقيٍّ؛ في السجلِّ اليومَ صفٌّ واحدٌ كذلك: `cd0d7409`). القيمةُ غيرُ الصالحةِ تعودُ إلى الافتراضيّ.
- **لمَ 4؟** بـp ≈ 0.08 المقيسة وبافتراضِ الاستقلال: خطأُ صفٍّ ≈ p⁴ ≈ 4×10⁻⁵، ولقرابةِ 13 صفًّا ≈ 5×10⁻⁴ للتشغيل (بثلاثٍ ≈ 7×10⁻³). وإن ارتبطت اللقطاتُ فالأثرُ إخفاقٌ مرئيٌّ لا نجاحٌ صامت. **لم يُقَس** الارتباطُ الزمنيُّ بين اللقطات.
- لا تكرارَ لمهلةِ الـ45 ث في كلِّ محاولةٍ خارجيّة: خطأُ الواجهةِ يُنهي البحثَ فورًا، فالحدُّ الأقصى للصفِّ يبقى قريبًا ممّا كانَ.
- كلُّ صفٍّ مقيسٍ يطبعُ سطرَ تشخيصٍ: رقمُ المحاولةِ التي وجدت السير، وعددُ الفارغِ وغيرِ الصالحِ قبلَها.
- **لم يتغيّر:** معيارُ `real`/`blackout` (`started`)، ومحاولاتُ `_gh_read`، ووجهُ «الجزئيِّ المعلَن» بلا واجهة، وأيُّ صفٍّ في `CI_VERDICT_AUDIT.md`.
