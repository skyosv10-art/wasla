# قوائم سماح حدّ القناة (ADR-069 · §6-2 · المرحلة 2)

كل ملف `<surface>.json` يمثل سطحًا واحدًا (تطبيق Mini App) وكل مدخل فيه يصف
مسارًا واحدًا يفتحه الحدّ لذلك السطح. الحارس `edge-allowlist-guard` (الفحص 28)
يقرأ هذه القوائم ويرفض أي انحراف عن الشفرة الفعلية أو عن قرار ADR-069 §2.8.

- الصيغة المطلوبة لكل مدخل: `{method, path, service, class, required_scopes, evidence_tests[]}`.
- `class` من التصنيف §2.8 حرفيًا: `O` (ملكية بـ`obo`) · `P` (قراءة عامة) · `W` (تعتمد على `wua1`) · `N` (بلا ربط ملكية) · `ADM` (إدارة).
- قاعدة الفتح: `production_open: true` مسموحة لـ`O` فقط (مع `evidence_tests` غير فارغة تشير إلى حالات E-18/E-19 على المسار نفسه)، ولافتتاح `P` إلا بعد دليل E-20 (لم يُكتب بعد — كل مدخلات `P` تُفتح لاحقًا بقرار مالك مستقل)، ولا `W` قبل G-ENF للخدمة، ولا `N` قبل حارس ملكية مختبر، ولا `ADM` قبل المرحلة 4.
- `required_scopes` يُقاس من الشفرة (`ownerScoped(...)` · `assertedStaff(...)` · ...) — لا يُخترع.
- `production_open: false` يعني أن المدخل مسجَّل للعرض والقياس لكن لا يُفتح للإنتاج.

الحقيقة الحالية للقوائم: قائمة الإنتاج **فارغة عمدًا** (O مفتوحة تتطلب E-18/E-19 على المستقبل في `off` — لم تُكتب بعد). القوائم موجودة لتوثيق التصنيف الحالي ولِيحرسَها الحارس ضد الانحراف، لا لفتح الإنتاج.
