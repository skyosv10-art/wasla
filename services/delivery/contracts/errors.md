# كتالوجُ أخطاءِ خدمةِ التوصيلِ (Delivery Errors)

> **القاعدة:** الخطأ كودٌ ثابتٌ لا نصٌّ حرٌّ. النصُّ للسجلِّ والتوثيقِ، والكودُ
> للتعدادِ والتنبيهِ. أيُّ خطأٍ جديدٍ = سطرٌ هنا + تعريفٌ في نطاقِ الخدمةِ +
> سببٌ مغلقٌ إن كان قراراً.
>
> المرجعُ الحاكمُ: ADR-026 (حدودُ طلباتِ المتجرِ والتوصيلِ) · ADR-004 (العقدُ
> قبلَ التنفيذِ) · ADR-001 (الخصوصيّةُ بالتصميمِ).

## البنية

```json
{
  "error_code": "DELIVERY_XXX",
  "message": "رسالةٌ تشخيصيّةٌ للسجلِّ لا للمستخدمِ",
  "trace_id": "..."
}
```

## كتالوجُ الأخطاء

| الكود | المعنى | الشرط |
|---|---|---|
| `DELIVERY_VALIDATION_FAILED` | مدخلاتٌ غيرُ صالحةٍ (كميّةٌ صفريةٌ · مرجعٌ غيرُ مطابقٍ) | قبلَ أيِّ قرارٍ |
| `DELIVERY_ORDER_NOT_FOUND` | طلبُ متجرٍ غيرُ موجودٍ | القراءةُ |
| `DELIVERY_TASK_NOT_FOUND` | مهمّةُ توصيلٍ غيرُ موجودةٍ | القراءةُ |
| `DELIVERY_TRANSITION_NOT_ALLOWED` | انتقالُ حالةٍ لا تسمحُه آلةُ الحالاتِ (ADR-026 §3) | أيُّ انتقالٍ |
| `DELIVERY_CANCEL_NOT_ALLOWED` | الطلبُ تجاوزَ آخرَ نقطةِ إلغاءٍ (تُسلِّمُ للمندوبِ) | الإلغاءُ |
| `DELIVERY_PAYMENT_NOT_AUTHORIZED` | لا انتقالَ إلى confirmed إلا بpayment_state=authorized (ADR-026 §2.2) | التأكيدُ |
| `DELIVERY_INVALID_PROOF` | تسليمٌ بلا إثباتٍ أو إثباتٌ على حالةٍ غيرِ مُسلَّمةٍ (ADR-026 §2.4) | التسليمُ |
| `DELIVERY_SUBSTITUTION_NOT_ALLOWED` | استبدالُ صنفٍ خارجَ مرحلةِ الانتقاءِ (picking) (ADR-026 §2.5) | الاستبدالُ |
| `DELIVERY_SUBSTITUTION_WRONG_STORE` | البديلُ من متجرٍ آخرَ — مسموحٌ فقط داخلَ المتجرِ نفسِهِ (ADR-026 §2.5) | الاستبدالُ |
| `DELIVERY_INELIGIBLE` | طلبٌ خارجُ تغطيةِ التوصيلِ أو متجرٌ لا يستقبلُ طلباتٍ | الأهليّةُ |
| `DELIVERY_MARKETPLACE_UNAVAILABLE` | تعذَّرَت قراءةُ الأهليّةِ من السوقِ عبرَ الحدِّ المتَّفقِ عليهِ (ADR-026 §2.3) | الإنشاءُ |
| `DELIVERY_DISPATCH_UNAVAILABLE` | تعذَّرَ تفويضُ dispatch — المهمّةُ تبقى في eligible و`retry` | التفويضُ |
| `DELIVERY_CONCURRENT_UPDATE` | تعارضُ نسخةٍ (optimistic concurrency) — يُعادُ الطلبُ | التحديثُ |
| `DELIVERY_INTERNAL_ERROR` | خطأٌ غيرُ مُصنَّفٍ عبرَ حدِّ HTTP (عيبٌ أو تعذُّرُ قاعدةٍ غيرُ مُترجَمٍ) — **لا يُعادُ الطلبُ تلقائيّاً بلا مفتاحِ تماثُلٍ** | أيُّ مسارٍ |
| `DELIVERY_IDEMPOTENCY_KEY_REUSED` | `Idempotency-Key` نفسُهُ بطلبٍ مختلفِ البصمةِ — رفضٌ لا إعادةُ جوابِ الطلبِ الأولِ | المسارانِ الكاتبانِ |
| `DELIVERY_IDEMPOTENT_REQUEST_IN_FLIGHT` | مفتاحٌ نفسُهُ يُعالَجُ الآنَ في معاملةٍ أخرى — لا كتابةَ ثانيةً، والإعادةُ تُعيدُ جوابَ الأولِ | المسارانِ الكاتبانِ |
| `DELIVERY_DATABASE_UNAVAILABLE` | مسبارُ الجاهزيّةِ سألَ القاعدةَ فلم تُجِب في المهلةِ | `GET /delivery/ready` |

## قواعدُ الاستخدام

1. **لا نصوصَ حرّةً للعميلِ:** رسالةُ القناةِ تُشتقُّ من الكودِ ومسارِ
   التوطينِ — لا من `message`.
2. **الخطأُ قرارٌ أيضاً:** كلُّ خطأٍ منعيٍّ يُسجَّلُ في دفترِ الانتقالاتِ
   (`*_transitions`) سببُهُ الكودُ نفسُهُ، فلا يختفيَ قرارٌ منعٍ بصمتٍ.
3. **التبعيّاتُ تُفشلُ بصوتٍ عالٍ:** تعذُّرُ السوقِ أو dispatch يُرجِعُ
   `DELIVERY_MARKETPLACE_UNAVAILABLE` / `DELIVERY_DISPATCH_UNAVAILABLE` —
   لا قيمةَ صامتةً ولا تخميناً (ADR-026 §2.3 · §2.4).
4. **الخطأُ غيرُ المُصنَّفِ لا يستعيرُ كوداً (المراجعةُ 6/N):** ما لا يكونُ
   `DeliveryError` عندَ حدِّ HTTP يخرجُ `500 DELIVERY_INTERNAL_ERROR` — لا
   بجسمٍ خارجَ `ErrorResponse` (فيكسرَ كلَّ مستهلكٍ) ولا بكودٍ يعني شيئاً
   آخرَ («تعذَّرَ السوقُ» ليس اسماً لعيبٍ في الشيفرةِ). ولا يُصنَّفُ 503
   خلافاً لسابقةِ البحثِ: `POST /store-orders` بلا مفتاحِ تماثُلٍ في هذا
   العقدِ، فدعوةُ العميلِ إلى الإعادةِ قد تُنشئُ طلبَينِ — و**مفتاحُ
   التماثُلِ دَينٌ مُعلَنٌ** (ADR-026 §4.9-3).
5. **مفتاحُ التماثُلِ يُبدِّلُ معنى الإعادةِ لا معنى الكودِ (المراجعةُ 7/N):**
   `Idempotency-Key` صارَ **إلزاميّاً** على المسارَينِ الكاتبَينِ، فأصبحَ
   «أعِد الطلبَ نفسَهُ بالمفتاحِ نفسِهِ» تعليماً آمناً: الإعادةُ تُعيدُ جوابَ
   الطلبِ الأولِ حرفاً (`Idempotent-Replay: true`) ولا تكتبُ شيئاً. ومع ذلك
   **يبقى الملاذُ الأخيرُ 500 لا 503**: 503 يعني «التبعيّةُ غائبةٌ فأعِد»،
   والعيبُ غيرُ المُصنَّفِ ليس غياباً لتبعيّةٍ — وقد يكونُ الطلبُ نُفِّذَ.
   المفتاحُ يجعلُ إعادةَ العميلِ **آمنةً** لا **مُستحسنةً**، والفرقُ مقصودٌ:
   قرارُ المراجعةِ 6/N أُعيدَ النظرُ فيه صراحةً هنا كما تعهَّدَ ADR-026 §4.9-3.
6. **الجاهزيّةُ لا تكذبُ:** `GET /delivery/ready` يسألُ القاعدةَ فعلاً
   (`SELECT` على جدولٍ حقيقيٍّ بمهلةٍ)، ويُجيبُ `503` بجسمِ الجاهزيّةِ نفسِهِ
   لا بجسمِ الخطأِ — المسبارُ يقرأُ حالةً لا كتالوجَ أخطاءٍ. وما لا يُسبَرُ
   (منفذُ الكتالوجِ غيرُ الموصولِ) يُذكَرُ في `not_claimed` ولا يُحسَبُ جاهزيّةً.
7. **لا بياناتِ شخصيّةَ في الأخطاءِ:** الكودُ يحملُ مراجعَ opaque فقط — لا
   اسمٍ ولا هاتفٍ ولا عنوانٍ (ADR-026 §2.6).
