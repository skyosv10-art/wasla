# كتالوج أخطاء خدمة التوزيع — Dispatch Errors

- **Scope:** أكواد أخطاء `services/dispatch` وأكواد أسباب نتائج المهمة والموجة والعرض (`reason_code`).
- **Last Updated:** 2026-08-21
- **Status:** Active (Phase 07 · MR 1/6 — عقد فقط، لا تنفيذ بعد)
- **Related Code:** [`api.openapi.yml`](api.openapi.yml) · [`events.json`](events.json) · [`schema.sql`](schema.sql) · [ADR-011](../../../docs/15-decisions/ADR-011-matching-dispatch-separation-candidate-source-and-tick-driven-time.md)
- **Related Team:** Team 05 — Dispatch

## القاعدة

كل خطأ **كود ثابت** يقرأه البرنامج ورسالة يقرأها الإنسان؛ الاختبار يتحقق من الكود لا من النص،
فتغيير الصياغة لا يكسر المستهلك وتغيير الكود تغيير عقد. وكل `reason_code` كود مغلق: السبب الحر
لا يُجمع في التحليلات وقد يعبر إلى الحدث كنص لا ينبغي أن يخرج من حدّ الخدمة.

المهمة والعرض والموجة لا ينتهون بلا سبب. لذلك يستعمل التنفيذ الأكواد هنا في الصف وسجلّ التدقيق
والحدث معاً، لا رسالة HTTP متبدلة. الاستثناء هو الحالة المعلّقة (`pending` أو `dispatching` أو
`offered`) لأنها لم تصل نتيجة بعد.

## أصناف الأخطاء

| الصنف | HTTP | متى |
|---|---:|---|
| `validation_error` | 400 | الجسم أو المعامل أو الرأس لا يطابق العقد شكلياً |
| `not_found` | 404 | مهمة أو عرض غير موجود في خدمة التوزيع |
| `conflict` | 409 | تعارض حالة أو إعادة مفتاح بحمولة مختلفة أو قرار حُسم بالفعل |
| `unprocessable` | 422 | الحمولة مفهومة لكن غير مقبولة منطقياً أو رُفضت نهائياً من محرك الطلبات |
| `service_unavailable` | 503 | التخزين أو منفذ إلزامي غير متاح، والمحاولة اللاحقة بالمفتاح نفسه لازمة |

## أكواد الأخطاء

| الكود | HTTP | المعنى | ملاحظة للمستهلك |
|---|---:|---|---|
| `DISPATCH_VALIDATION_FAILED` | 400 | الجسم أو معامل المسار أو الرأس لا يطابق العقد | صحح المدخل قبل إعادة المحاولة |
| `DISPATCH_JOB_NOT_FOUND` | 404 | لا مهمة بهذا المعرّف | لا تستنتج من الجواب شيئاً عن جدول الطلبات |
| `DISPATCH_OFFER_NOT_FOUND` | 404 | لا عرض بهذا المعرّف | العرض حدّ توزيع لا سجل إسناد orders |
| `DISPATCH_IDEMPOTENCY_KEY_REUSED` | 409 | استُخدم `Idempotency-Key` نفسه بحمولة مختلفة | لا تعالج المفتاح كمعرّف جلسة |
| `DISPATCH_JOB_ALREADY_EXISTS` | 409 | للطلب مهمة توزيع قائمة أو نهائية | طلب واحد لا يخلق منسقين متنافسين |
| `DISPATCH_JOB_NOT_CANCELLABLE` | 409 | المهمة أُسندت أو استُنفدت أو ألغيت سابقاً | النتيجة النهائية لا تُكتب مرتين |
| `DISPATCH_OFFER_ALREADY_RESOLVED` | 409 | العرض مقبول أو مرفوض أو منتهٍ أو ملغى | النبضة والعميل قد يتسابقان؛ القاعدة تحسم |
| `DISPATCH_OFFER_SUPERSEDED` | 409 | فاز عرض آخر للمهمة قبل محاولة هذا العرض | ليس رفضاً من السائق |
| `DISPATCH_WAVE_ALREADY_OPEN` | 409 | حاولت العملية فتح موجة ثانية نشطة للمهمة | الفهرس الجزئي هو حارس السباق |
| `DISPATCH_REASON_CODE_REQUIRED` | 422 | نتيجة نهائية بلا `reason_code` | لا نهاية بلا سبب قابل للتحليل |
| `DISPATCH_REASON_CODE_UNKNOWN` | 422 | الكود ليس من الكتالوج أدناه | لا يقبل نصاً حراً بدلاً من كود |
| `DISPATCH_JOB_NOT_DISPATCHABLE` | 422 | الطلب أو المهمة لا تسمح ببدء تنسيق جديد | لا يعالج ذلك باختيار مرشح بديل محلياً |
| `DISPATCH_ORDER_ENGINE_REJECTED` | 422 | محرّك الطلبات فهم طلب العرض أو الحسم ورفضه نهائياً | لا يعاد بنفس المفتاح ولا ينسخ التوزيع آلة الحالة |
| `DISPATCH_MATCHING_RESULT_INVALID` | 422 | نتيجة المطابقة لا تصلح لفتح موجة في لقطة المهمة | خطأ حدّ عقود، لا تُعاد كتابة الأهلية هنا |
| `DISPATCH_ENGINE_UNAVAILABLE` | 503 | التخزين أو `orders` أو `matching` غير متاح | أعد المحاولة بالمفتاح نفسه |
| `DISPATCH_ORDER_ENGINE_TIMEOUT` | 503 | لا جواب من محرّك الطلبات قبل المهلة | غموض مسجل، لا يتحول إلى رفض أو عدم توفر |

## كتالوج أكواد الأسباب (`reason_code`)

القائمة **مقفلة**: إضافة كود تغيير عقد يوثق في `TASK_LOG`. الأحداث لا تحمل إلا هذه الأكواد؛
ولا يحمل أي منها نصاً كتبه سائق أو عميلاً أو مشرفاً.

### نتائج العرض

| الكود | الحالة الناتجة | المعنى |
|---|---|---|
| `OFFER_ACCEPTED` | `accepted` | قبل السائق العرض الفائز |
| `DRIVER_DECLINED` | `rejected` | رفض السائق العرض صراحة |
| `DRIVER_UNAVAILABLE` | `rejected` | أفاد السائق أنه لم يعد متاحاً |
| `DRIVER_VEHICLE_ISSUE` | `rejected` | المركبة لا تسمح بهذا العرض |
| `OFFER_TIMED_OUT` | `timed_out` | انتهت المهلة المخزنة بلا جواب |
| `OFFER_SUPERSEDED` | `superseded` | قبول عرض آخر حسم المهمة، فألغي العرض الآخر |
| `JOB_CANCELLED` | `cancelled` | ألغيت المهمة فأُلغي العرض المفتوح |

### نتائج الأمواج والتصعيد

| الكود | الحالة الناتجة | المعنى |
|---|---|---|
| `WAVE_OFFERS_RESOLVED` | `completed` | حُسمت كل عروض الموجة بلا قبول فائز |
| `ALL_WAVES_EXHAUSTED` | `escalated_community` | انتهى حد الأمواج؛ قرار التصعيد مسجل لكن التوصيل مِلْك القناة |
| `NO_DRIVER_AVAILABLE` | `exhausted` | انتهى التصعيد بلا قبول، فينتقل الطلب عبر منفذ orders إلى `no_driver_found` |
| `ORDER_ENGINE_REJECTED` | `cancelled` | رفض محرك الطلبات نهائياً متابعة تنسيق هذه المهمة |

### إلغاء المهمة

| الكود | الحالة الناتجة | المعنى |
|---|---|---|
| `ORDER_CANCELLED` | `cancelled` | أُلغي الطلب عند مالكه، فلا يبقى تنسيق بلا طلب |
| `DISPATCH_CANCELLED_BY_REQUESTER` | `cancelled` | أوقف المالك أو التشغيل مهمة التوزيع صراحة |
| `ORDER_ENGINE_REJECTED` | `cancelled` | منع المحرك نهائياً العرض أو الحسم المطلوب |

## تصنيف أجوبة محرّك الطلبات

التوزيع لا يعيد تعريف حالة الطلب ولا «يصلح» جواب محركه؛ يصنفه كي تبقى إعادة المحاولة والنتيجة
التجارية منفصلتين:

| جواب محرّك الطلبات | تصنيف التوزيع | الأثر |
|---|---|---|
| `409` أو `422` | **رفض نهائي** | يسجل `ORDER_ENGINE_REJECTED`/`DISPATCH_ORDER_ENGINE_REJECTED` ولا يعيد النداء بنفس المفتاح؛ الحاكم قبل أو رفض وفق آلة حالته |
| أي `4xx` آخر | **خطؤنا** | يسجل عيب الحد أو الطلب ويوقف المسار المتأثر؛ لا يصنفه رفض سائق ولا مرشح غير متاح |
| `5xx` أو انقطاع | **قابل لإعادة المحاولة** | يحتفظ بالمفتاح الحتمي المشتق من `(offer_id, action)` ويعيد النداء به؛ لا يولد عرضاً ثانياً |
| لا جواب قبل المهلة | **`TIMEOUT` غموض مسجل** | لا يدمج الغموض في «غير متاح»؛ قد يكون المحرك نفذ الكتابة قبل ضياع الجواب، فتجب الإعادة بالمفتاح نفسه |

**لماذا لا يعدّ الرفض أو المهلة خطأ HTTP:** هما نتائج عمل متوقعة تُكتب بسبب وتنتج حدثاً؛ جعلهما
خطأً يخفي سجلاً يحتاجه فتح الموجة التالية والتدقيق.
